# 性能军师 · Frontend Perf Optimizer

> 分类：开发编程 ｜ 版本：v1.0.0 ｜ 链接：https://skillhub.cn/skills/user_ac54d1c1/frontend-perf-optimizer

## 一句话简介
前端性能优化诊断器——既帮你把性能优化落到实处，也帮你系统梳理"性能优化怎么做"的思路课题。当用户要求"帮我优化性能 / LCP慢怎么改 / 页面卡顿 / 首屏慢 / 秒开怎么做到 / 怎么提升Core Web Vitals / 分析这段性能数据、performance日志或trace / 长任务怎么处理 / 用AI辅助做性能归因、生成优化补丁或性能评审 / 系统梳理性能优化思路、如何借力AI提效做性能优化"，或提供 Lighthouse/WebPageTest/RUM 报告、performance 数据、代码仓库或场景说明并要求做性能诊断与优化时使用。核心是"分层治理 + ROI 决策 + AI 辅助"：消化多形态输入，输出性能画像 + 分层优化架构（L1/L2/L3 每层动作/ROI/验证）+ 按场景的优先级决策 + 用大模型做归因/补丁/评审。

## 一句话定位
**Lighthouse 告诉你页面有多慢；这个 skill 告诉你先改什么、怎么改、能提升多少。**

## 核心职责
把"性能优化"变成**分层治理路径 + ROI 决策 + AI 辅助闭环**：
1. **消化多形态输入**：报告 / trace / 代码 / 场景描述，都能转成可诊断的画像。
2. **输出优化分层架构**：按投入产出比分 L1/L2/L3 三层，每层给动作 + ROI 量级 + 验证口径。
3. **给当前场景的优先级决策**：明确"现在最该做哪一层、哪个动作"。
4. **引入 AI 辅助（AI-native）**：按 `AI-ASSISTED.md` 方法论，用大模型做归因、生成补丁、性能评审、监控归因。

## 性能治理闭环
```
诊断(Analyze) → 优化(Optimize) → 验证(Validate) → 防劣化(Guard) → 监控(Monitor)
```
每个优化方案除动作外，**必带"防劣化 & 监控建议"区块**——让 skill 既是优化工具，也是性能治理思维载体。

## 分层优先级原则
- **先 L1 后 L2 再 L3**：零成本高 ROI 先做；架构级高成本做前必须权衡投入产出。
- **不越层空谈**：L1 没做就去谈架构改造是浪费。
- **ROI 必带验证**：每层每个动作给 ROI 量级 + 验证口径，不做不可证伪的承诺。

## 澄清引导协议（模糊开场时强制）
用户只说"帮我做性能优化 / 给点建议"等极简输入时，**先给全局框架再系统引导**：
1. **先给高层框架**（1 段）：性能优化按投入产出分三层——资源与配置（L1，高 ROI）、代码与运行时（L2）、架构与体验（L3）。
2. **按固定维度一次性问清**：项目形态（新/存量）、运行形态（H5/小程序/动态化/跨端/SSR）、业务场景、目标（首屏/交互/布局稳定/秒开）、已有数据（报告/trace/代码/无）。
3. 用户补全后按主流程执行；仍缺的信息列入"待确认"，不编造。

## 对标边界
Lighthouse/WebPageTest 做检测，RUM 平台做采集，本 skill 做**分层治理、决策与 AI 辅助闭环**——补齐"知道慢 → 知道先改什么、按什么逻辑改、如何借力 AI 提效"的空白。
