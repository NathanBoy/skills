# Agent 架构拆解器 · Agent Arch Deconstructor

> 分类：开发编程 ｜ 版本：v1.0.0 ｜ 下载：8 次 ｜ 链接：https://skillhub.cn/skills/user_ac54d1c1/agent-arch-deconstructor

## 一句话简介
Agent 架构拆解器。当用户要求"拆解这个 agent / 这个工作流怎么运作 / 这是什么架构 / 是 ReAct 还是 CoT / 帮我分析这段 agent 代码或配置 / Loop 和 Harness 工程是什么"，或上传 agent 工作流、编排代码、prompt 模板、多轮日志并要求理解其推理范式与执行机制时使用。把任意 Agent 实现拆解成 ReAct/CoT/Plan-Execute/Loop/Harness/RAG 等范式，用架构图呈现执行链路，并标注每个环节的输入输出与大致 token 成本。

## 核心职责
把一段 agent 工作流/代码/配置/日志，拆成**可理解的架构**：识别其推理范式、执行循环、工具编排与上下文管理，用 Mermaid 架构图呈现链路，并给出每个环节的 token 成本量级。

## 工作流程
1. **收集输入**：确认要拆解的对象——一段代码、一份 prompt/配置、一段多轮 agent 日志，或一个口头描述的工作流。
2. **静态扫描（硬证据）**：对代码/配置/日志运行 `arch_analyzer.py`，得到各范式的关键词命中得分表，作为识别的事实依据（可对目录递归扫描）。
3. **识别范式**：结合扫描得分与 `PATTERNS.md` 的判别特征判断属于哪种。**扫描得分高≠一定是该范式**，须结合代码行为人工研判，并引用具体证据片段。
4. **拆执行链路**：画出从输入到输出的每一步——谁做决策（LLM 还是规则）、是否循环（ReAct 的 think-act-observe；Loop 的迭代条件与终止）、工具如何被调用/回喂、上下文如何注入/压缩/裁剪。
5. **标 token 成本**：对每个 LLM 调用环节，估算 input/output token 量级，标注"估算"。
6. **输出报告**：固定格式输出，含架构图，交付前过质量门。

## 架构图规范
- 用 Mermaid `flowchart`，节点命名用中文标签。
- 循环用回边明确标出（ReAct 的 think→act→observe→think）。
- 每处 LLM 调用在节点旁注 `~N tokens`。
- 多 agent 协作时按角色分区（Planner / Worker / Critic）。

## 常见失败点（Gotchas）
- **把关键词命中当范式定论**：扫描命中高不等于就是该范式，须看控制流与调用关系。
- **多范式漏识别**：现代 agent 常是 Harness+ReAct+RAG 叠加，漏任何一个都会误导读者。
- **token 估算失真**：只估输出长度会严重低估——ReAct/Loop 的成本是"轮数 × 每次回带的上下文"。
- **架构图画成流水线**：没有循环回边/分支的图会把 agent 画成单线管道。
- **空谈范式名词**：每个范式结论都要能指到代码里的具体位置。

## 约束
- 识别要有证据：引用代码/日志/配置里的具体片段，不空谈范式名词。
- token 一律标"估算"，说明依据（调用次数 × 平均上下文）。
- 没把握的范式组合，明确说"疑似 X+Y 混合"，不强行下结论。
